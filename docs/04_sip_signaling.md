# Lesson 04: SIP (Session Initiation Protocol) & VoLTE / VoNR Call Control

## Overview

**SIP (Session Initiation Protocol)** is the signaling protocol used by the **IP Multimedia Subsystem (IMS)** to establish, modify, and tear down voice and video calls in 4G VoLTE and 5G VoNR networks. SIP is a text-based request/response protocol modeled after HTTP, running over UDP or TCP on port **5060** (or TLS on port **5061**).

This lesson covers:
- **RFC 3261**: Core SIP — URIs, headers, transactions, dialogs, REGISTER, INVITE, BYE, ACK
- **RFC 3262**: Reliability of provisional responses (`100rel` and `PRACK` method)
- **3GPP TS 24.229**: 3GPP IMS call control — compact headers, P-headers, registration procedures

### 3GPP Context

| Interface | Between | SIP Role |
|-----------|---------|---------|
| **Gm** | UE ↔ P-CSCF | UE registration and call signaling entry point |
| **Mw** | P-CSCF ↔ S-CSCF | IMS core proxy routing |
| **ISC** | S-CSCF ↔ AS | Application Server service invocation (VoLTE, RCS) |
| **Mg / Mi** | S-CSCF ↔ BGCF/MGCF | PSTN/CS interworking |

## 1. Protocol Structure

### SIP Request Structure (RFC 3261 §7.1)

```
INVITE sip:bob@ims.example.com SIP/2.0\r\n
Via: SIP/2.0/UDP 192.168.1.10:5060;branch=z9hG4bK-abc123;rport\r\n
From: <sip:alice@ims.example.com>;tag=1928301774\r\n
To: <sip:bob@ims.example.com>\r\n
Call-ID: a84b4c76e66710@192.168.1.10\r\n
CSeq: 1 INVITE\r\n
Contact: <sip:alice@192.168.1.10:5060>\r\n
Content-Type: application/sdp\r\n
Content-Length: 147\r\n
\r\n
[SDP body — Lesson 03]
```

### Core SIP Headers

| Header | Short | Purpose |
|--------|-------|---------|
| `Via` | `v` | Network path record; `branch` parameter is transaction ID |
| `From` | `f` | Originator URI + local `tag` (generated by UAC) |
| `To` | `t` | Destination URI + remote `tag` (assigned on 2xx) |
| `Call-ID` | `i` | Globally unique identifier for the entire call |
| `CSeq` | — | Monotonically increasing sequence number + method name |
| `Contact` | `m` | Direct routable URI for in-dialog requests |
| `Content-Type` | `c` | Body type — `application/sdp` for media negotiation |
| `Content-Length` | `l` | Body byte count |

### SIP Response Code Classes

| Class | Range | Meaning |
|-------|-------|---------|
| 1xx | 100–199 | Provisional — request received, processing |
| 2xx | 200–299 | Success |
| 3xx | 300–399 | Redirection |
| 4xx | 400–499 | Client Error |
| 5xx | 500–599 | Server Error |
| 6xx | 600–699 | Global Failure |

## 2. 3GPP Protocol Flow

### IMS VoLTE Call Flow (3GPP TS 24.229)

```
    UE (Alice)           P-CSCF          S-CSCF           UE (Bob)
        |                   |               |                  |
  1.    |--- REGISTER ------>|               |                  |
  2.    |<-- 200 OK ---------|               |                  |
        |                   |               |                  |
  3.    |--- INVITE -------->|---INVITE----->|----INVITE------->|
        |   (SDP Offer)      |               |   (SDP Offer)    |
  4.    |<-- 100 Trying -----|               |                  |
  5.    |<-- 180 Ringing ----|<--180 Ring----|<--180 Ringing----|
  6.    |<-- 200 OK  --------|<--200 OK------|<--200 OK --------|
        |   (SDP Answer)     |               |   (SDP Answer)   |
  7.    |--- ACK ----------->|---ACK-------->|----ACK---------->|
        |                   |               |                  |
        | <======= RTP Audio Media (Lesson 05) ===============> |
        |                   |               |                  |
  8.    |--- BYE ----------->|---BYE-------->|----BYE---------->|
  9.    |<-- 200 OK ---------|               |                  |
```

### SIP Dialog State Machine

```
 +--------+  INVITE Sent    +-------+  180 (with To-tag)  +-----------+
 |  IDLE  |---------------->| EARLY |-------------------->| CONFIRMED |
 +--------+                 +-------+                     +-----------+
                                                                |
                                                          BYE sent/rcvd
                                                                v
                                                         +------------+
                                                         | TERMINATED |
                                                         +------------+
```

### Demo Scenario — `demo_04_sip_volte_call.cpp`

Simulates a complete **IMS VoLTE call** over real UDP loopback sockets:

1. **REGISTER** — Alice registers at P-CSCF with `Expires: 3600`
2. **200 OK** (REGISTER) — P-CSCF confirms registration
3. **INVITE** — Alice sends call invite to Bob with SDP Offer (AMR-WB)
4. **180 Ringing** — P-CSCF relays ringing indication from Bob
5. **200 OK** (INVITE) — Bob answers with SDP Answer (AMR-WB matched)
6. **ACK** — Alice completes 3-way handshake, dialog enters `CONFIRMED`
7. **BYE** — Alice ends the call
8. **200 OK** (BYE) — P-CSCF confirms teardown; dialog → `TERMINATED`
9. All 8 messages captured to `output_04_sip_volte_call.pcap`

## 4. Key Engineering Concepts

### SIP Transaction vs Dialog
- A **Transaction** is a single Request + its responses (e.g. one INVITE + 100/180/200).
- A **Dialog** is the long-lived peer-to-peer relationship established by INVITE (identified by `Call-ID` + `From-tag` + `To-tag`). A dialog persists across multiple transactions (INVITE, re-INVITE, BYE).

### Compact Headers (RFC 3261 §7.3.3)
Cellular UEs on narrow radio channels transmit SIP over UDP with single-letter compact headers to minimize overhead: `v` (Via), `f` (From), `t` (To), `i` (Call-ID), `m` (Contact), `c` (Content-Type), `l` (Content-Length), `k` (Supported). The parser must handle both forms interchangeably (case-insensitive).

### Via `branch` Parameter — Transaction ID
Every SIP proxy adds a `Via` header with a unique `branch` tag prefixed by `z9hG4bK` (RFC 3261 magic cookie). This `branch` value is the transaction identifier used for routing responses back through the same path.

## 5. Wireshark Analysis

Open `output_04_sip_volte_call.pcap` and verify:

```
Frame 1: Alice → P-CSCF   SIP REGISTER   sip:alice@ims.example.com
Frame 2: P-CSCF → Alice   SIP 200 OK     (REGISTER)
Frame 3: Alice → P-CSCF   SIP INVITE     (SDP Offer: AMR-WB PT=104)
Frame 4: P-CSCF → Alice   SIP 180 Ringing
Frame 5: P-CSCF → Alice   SIP 200 OK     (SDP Answer: AMR-WB PT=104, sendrecv)
Frame 6: Alice → P-CSCF   SIP ACK
Frame 7: Alice → P-CSCF   SIP BYE
Frame 8: P-CSCF → Alice   SIP 200 OK     (BYE)
```

In Wireshark: navigate to **Telephony → VoIP Calls** to view the complete call flow diagram with registration, ringing, media answer, and teardown. The SDP body is visible in the INVITE and 200 OK messages under `Message body → Session Description Protocol`.

```bash
tcpdump -r output_04_sip_volte_call.pcap -nvX
```
